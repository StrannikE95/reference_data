# Модуль поиска

Поиск читает одно состояние одного кода. Им пользуется `GET /dictionaries/{dictionary_code}/values/{value_code}`. Отдельного хранилища адресов нет: строка ищется в секции `dictionary_row` этого справочника.

Актуальные данные и данные на момент ищутся одним способом. Меняется только условие периода.

# Вход

+ `dictionary_code`
+ `value_code`
+ список колонок ответа, уже собранный из паспорта
+ `at` либо признак, что нужен открытый период

Паспорт к этому моменту найден и активен. Неизвестная колонка до поиска отклоняется.

# Выбор строки

Секция задана `dictionary_code`.

Актуальные данные: строка с этим `value_code` и пустым `valid_to`. Открытое состояние одно.

На момент `at`: строка с этим `value_code`, у которой `valid_from <= at` и (`valid_to` пуст или `valid_to > at`). Конец периода в строку не входит: в момент `valid_to` действует уже следующее состояние.

Строки нет — ответ `result = absent`. Таблица дальше не читается.

# Сборка ответа

Колонки берутся из текущего `fields`, а не из ключей найденного `data`.

Для каждой колонки значение — `data[code]`. Ключа в документе нет — значение пустое. Лишние ключи документа, которых уже нет в паспорте, не отдаются.

Одна колонка отдаётся как `attribute` и `value`. Несколько колонок и полный список `*` отдаются объектом `attributes`.

# Пример

Паспорт `wall_material`, колонки по порядку: `name` (`default`), `kind_code`, `is_bearing`, `density`. `kind_code` — обычная колонка типа `string`, в ней код вида стены.

`dictionary_row`, секция `wall_material`

| value_code | valid_from | valid_to | data |
| --- | --- | --- | --- |
| BRICK | 2024-01-01T00:00:00Z | 2026-10-20T00:00:00Z | `{"name":"Кирпич","kind_code":"STONE","is_bearing":true,"density":1800}` |
| BRICK | 2026-10-20T00:00:00Z | | `{"name":"Кирпич керамический","kind_code":"STONE","is_bearing":true,"density":1800}` |
| TIMBER | 2024-01-01T00:00:00Z | | `{"name":"Брус","kind_code":"WOOD","is_bearing":false,"density":500}` |

Запрос без `attribute` и без `at` для `BRICK` берёт открытую строку и колонку по умолчанию: `name` = «Кирпич керамический».

Запрос `attribute=density` и `at=2024-06-01T00:00:00Z` для `BRICK` берёт первую строку: `value` = `1800`.

Запрос `attribute=name` и `attribute=density` без `at` для `BRICK` возвращает объект из открытой строки: `name` = «Кирпич керамический», `density` = `1800`.

Запрос `attribute=*` и `at=2024-06-01T00:00:00Z` для `BRICK` возвращает все четыре колонки паспорта из первой строки, включая `kind_code` = `STONE`.

Запрос `attribute=kind_code` возвращает эту строку кода и не подставляет название вида. Название запрашивается отдельно: код справочника вида, код `STONE` и тот же момент.
