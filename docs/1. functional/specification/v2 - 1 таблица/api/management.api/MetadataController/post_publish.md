# [На главную](../../../API.md)

# Описание

POST **/admin/dictionaries/{dictionary_code}/versions/{version_id}/publish**
Перевести черновик в активную версию. Прежняя активная версия закрывается. Если колонки отличаются от активной версии, публикация ждёт полную черновую строку на каждый открытый код.

# Входные параметры

+ `dictionary_code`:
    + path
    + Обязательно
    + `^[a-z][a-z0-9_]{0,62}$`
+ `version_id`:
    + path
    + Обязательно
    + Целое от 1

Тела нет.

# Поля ответа

+ `dictionary_code`
+ `version_id`
+ `status` = `active`
+ `valid_from`
+ `valid_to` — пусто

# Алгоритм работы

## Валидация

1. Проверить путь.
    + Нарушение:
        + Код: `invalid_request`
        + Статус: `400`
2. Найти паспорт по коду без учёта регистра.
    + Нет:
        + Код: `dictionary_not_found`
        + Статус: `404`
3. Найти версию с этим `version_id`.
    + Нет:
        + Код: `version_not_found`
        + Статус: `404`

## Бизнес-логика

1. Версия не `draft`:
    + Код: `version_not_draft`
    + Статус: `409`
2. Паспорт `inactive`:
    + Код: `dictionary_inactive`
    + Статус: `409`
3. Если есть версия `active` и колонки черновика отличаются от неё по набору `field_id`, `code` или `type`:
    + для каждого `value_code` с опубликованной строкой и пустым `valid_to` нужна строка `row_status = draft` этого `version_id`
    + `data` этой строки содержит ровно `code` колонок черновика, значение каждого совпадает с его `type`
    + кода или полного `data` нет:
        + Код: `reload_required`
        + Статус: `409`
4. Взять момент `T` — время этого запроса. Начать транзакцию.
5. Если есть версия `active`, поставить ей `closed` и `valid_to = T`.
6. Черновику поставить `active` и `valid_from = T`. `valid_to` оставить пустым.
7. Для каждой строки `dictionary_row` с `row_status = draft` и `version_id` этого черновика:
    + у опубликованной открытой строки того же `value_code` записать `valid_to = T`, если она есть
    + черновой строке поставить `row_status = published`, `valid_from = T`, `valid_to` пуст
8. Зафиксировать транзакцию. Вернуть статус `200`.

```mermaid
flowchart TD
  draft{"Версия draft"} -->|нет| bad["409 version_not_draft"]
  draft -->|да| live{"Паспорт не inactive"}
  live -->|нет| off["409 dictionary_inactive"]
  live -->|да| diff{"Колонки отличаются от active"}
  diff -->|да| ready{"Полная черновая строка у каждого открытого кода"}
  diff -->|нет| close["Закрыть прежнюю active"]
  ready -->|нет| reload["409 reload_required"]
  ready -->|да| close
  close --> pub["Черновик становится active"]
  pub --> rows["Черновые строки входят в период с T"]
  rows --> ok["200"]
```

Пока активной версии нет, сравнивать колонки не с чем и перезаливать нечего. Отличие только в `name` или `default` перезаливку не требует. Закрытые периоды не перезаливаются. Новые коды, которых не было в открытых строках, в эту проверку не входят. После публикации версии `draft` нет: запрос с `draft` получает `draft_not_found` и статус `404`, как запрос версии, которой нет. Ставшие активными строки в этот ответ не подставляются.
