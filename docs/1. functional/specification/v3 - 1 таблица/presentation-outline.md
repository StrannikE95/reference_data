# Оглавление и тезисы

## 1. Задача

- Две роли: 
    - Админ управляет схемой и данными (создать справочник, открыть черновик, править колонки и значения, опубликовать, удалить черновик, деактивировать)
    - Пользователь только читает (список справочников, колонки, значение по коду)

- Справочник. Состяния:
    - Активные
    - Закрытый
- Версии справочника. Состояния:
    - Черновик (один на справочник)
    - Активный (один на справочник)
    - Закрытый
- Версия схемы содержит колонки. Версия данных содержит строки и ссылку на схему, в которой они записаны.

- Схема справочника меняется, история значений не теряется.

## 2. Модель

- Четыре таблицы: 
    - Паспорт: 
        - код, название, владелец, `active`/`inactive`.
    - Версия схемы: 
        - Статус `draft`/`active`/`closed`, период, полная схема: код колонки, наименование, тип и остальные свойства.
    - Версия данных: 
        - Статус `draft`/`published`, ссылка на схему, `type` — `delta` или `full`.
    - Строка: 
        - Поля `value_code`, `data_version_id`, `status`, период, `data`.
        - Строка помнит версию данных. Схема строки — схема этой версии данных.

- Поэтому старые значения читаются по старой схеме.
- Атрибут `name` есть в каждой версии: обязательный, тип `string`, не удаляется. Он же атрибут по умолчанию. В UI его не выбирают.

## 4. Одна таблица значений

- Все справочники пишут в `dictionary_row`, секция на `dictionary_code`.
- Секция создаётся вместе с паспортом (ее имя — производное от кода)

## 5. Две версии

- Черновик схемы и черновик данных живут отдельно. У каждого не больше одного.
- Правка значения открывает версию данных `delta` на активную схему. Схему не открывает. Открытая строка не закрывается.
- Смена состава или установка обязательности открывает версию данных `full` на черновик схемы.
- Черновые строки не видны запросам без `draft=true`.
- Пока черновик открыт, пользователь видит прежние открытые данные.

## 6. Публикация строк

- Публикация `delta` на активной схеме схему не закрывает.
- `full` выбирается на экране и передаётся в путь публикации. Закрываются все ранее открытые записи и открываются новые. Новая схема не обязательна. Загрузка файла пойдёт тем же типом, разбор файла не описан.

## 7. Публикация схемы

- `T` — время запроса публикации.
- Прежняя `active` → `closed`, `valid_to = T`. Черновик → `active`, `valid_from = T`.
- Всё одна транзакция: двух активных версий не бывает.

## 8. Карта API

- `admin`: 7 методов на схему, 6 на данные. Публикация значений — отдельный метод.
- `service`: список активных, колонки, значение по коду.
- Разница не в правах, а в видимости.
- Service не отдаёт черновик без `draft=true` и не отдаёт деактивированные справочники.

## 10. Чтение

- Три редакции: `active`, `history` по `at`, `draft`.
- `active` — открытая строка, даже если начало в будущем.
- `history` — строка, чей период покрывает `at`.
- `history` принимает и текущее имя колонки, и имя на момент.
- `draft` — только черновые строки; после публикации `404 draft_not_found`.
- Значение ищется по `field_id`: переименование не ломает старые данные.
- Тип проверяется в `active`/`draft`, в `history` — нет.

## 11. Экраны

- Справочники, паспорт, элементы.
- На структуре вкладки Active и Draft. «Создать» создаёт справочник, если его ещё нет, и открывает черновик, если справочник уже есть. Внизу Draft — форма данных черновика, без своих вкладок.
- Вкладки Active, Draft, History — у каждой своя таблица. На History дата, код и «Найти». На Draft «Начало» и «Конец» заполняются автоматически.
- На Draft ячейки редактируются. «Добавить запись» и правка пишут строку в версию данных. Черновика нет — открыть `delta` на активную схему.
- «Опубликовать» публикует черновик с типом `delta` или `full` и схему не меняет. `full` закрывает все открытые элементы.
- Поведение по ошибке выбирается по коду, текст — для человека.

## 12. Границы

- Нет прав, аудита, реактивации, удаления справочника целиком.
- «Одна активная версия» и «одна открытая строка» — правило кода, не DDL.
- `data` валидируется приложением, база ключи и типы не проверяет.
- `dictionary_code` в строках не внешний ключ — следствие партиций.
- Имя секции упирается в лимит идентификатора PostgreSQL 63 байта.
