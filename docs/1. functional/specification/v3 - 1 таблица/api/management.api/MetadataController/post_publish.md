# [На главную](../../../API.md)

# Описание

POST **/admin/dictionaries/{dictionary_code}/versions/{version_id}/publish**
Перевести черновик в активную версию. Прежняя активная версия закрывается. Если состав атрибутов изменился или атрибут стал обязательным, справочник должен быть перезалит: без этого черновик не публикуется.

# Входные параметры

+ `dictionary_code`:
    + path
    + Обязательно
    + `^[a-z][a-z0-9_]{0,62}$`
+ `version_id`:
    + path
    + Обязательно
    + Целое от 1

Тела нет.

# Поля ответа

+ `dictionary_code`
+ `version_id`
+ `status` = `active`
+ `valid_from`
+ `valid_to` — пусто

# Алгоритм работы

## Валидация

1. Проверить путь.
    + Нарушение:
        + Код: `invalid_request`
        + Статус: `400`
2. Найти паспорт по коду без учёта регистра.
    + Нет:
        + Код: `dictionary_not_found`
        + Статус: `404`
3. Найти версию с этим `version_id`.
    + Нет:
        + Код: `version_not_found`
        + Статус: `404`

## Бизнес-логика

1. Версия не `draft`:
    + Код: `version_not_draft`
    + Статус: `409`
2. Паспорт `inactive`:
    + Код: `dictionary_inactive`
    + Статус: `409`
3. Если есть версия `active` и состав атрибутов черновика отличается набором `field_id`, `code`, `type` или атрибут стал обязательным:
    + у каждого действующего элемента, строка которого опубликована и `valid_to` пуст, есть черновая строка этого `version_id`
    + в ней заполнен каждый атрибут с `required = true`. Атрибут с `required = false` может быть пустым
    + перезаливки нет:
        + Код: `reload_required`
        + Статус: `409`
4. Взять момент `T` — время этого запроса.
5. Для каждой черновой строки этого `version_id` найти опубликованную открытую строку того же `value_code`. Если она есть и `valid_from` черновой строки не строго позже `valid_from` открытой:
    + Код: `invalid_valid_from`
    + Статус: `409`
    + Ничего не менять
6. Начать транзакцию.
7. Если есть версия `active`, поставить ей `closed` и `valid_to = T`.
8. Черновику поставить `active` и `valid_from = T`. `valid_to` оставить пустым.
9. Для каждой строки `dictionary_row` с `row_status = draft` и `version_id` этого черновика:
    + у опубликованной открытой строки того же `value_code` записать `valid_to` = `valid_from` черновой строки, если она есть
    + черновой строке поставить `row_status = published`, `valid_to` пуст. `valid_from` не менять
10. Зафиксировать транзакцию. Вернуть статус `200`.

```mermaid
flowchart TD
  draft{"Версия draft"} -->|нет| bad["409 version_not_draft"]
  draft -->|да| live{"Паспорт не inactive"}
  live -->|нет| off["409 dictionary_inactive"]
  live -->|да| diff{"Состав изменился или атрибут стал обязательным"}
  diff -->|да| ready{"Справочник перезалит"}
  diff -->|нет| close["Закрыть прежнюю active"]
  ready -->|нет| reload["409 reload_required"]
  ready -->|да| close
  close --> period{"Начало черновой строки позже начала закрываемой"}
  period -->|нет| badFrom["409 invalid_valid_from"]
  period -->|да| pub["Черновик становится active"]
  pub --> rows["Строки публикуются со своим valid_from"]
  rows --> ok["200"]
```

Смена подписи или снятие обязательности перезаливку не требует. Установка обязательности требует. Атрибут по умолчанию — колонка `name`, публикация этот признак не меняет. После публикации запрос черновика отвечает так же, как на отсутствующую версию. Начало опубликованной строки остаётся `valid_from` черновика, и этим моментом закрывается прежняя открытая строка. Начало версии схемы — `T`.
