# UI администратора

Экраны администратора справочников. UI работает с простыми списками: у справочника одна таблица данных и версии этой таблицы. Поля версии читаются из `dictionary.JSON_metadata`. Колонки `source` нет. У версии нет своего `JSON_metadata`.

## 1. Общие правила

- Справочник описывается полями «Код», «Название» и «Владелец».
- Владелец вводится при создании и показывается в списке и на экране версий. Отдельного изменения паспорта нет.
- Код и название после создания не редактируются.
- Версия создаётся загрузкой CSV или JSON и остаётся черновиком. Пока черновик есть, вторая загрузка не принимается: его сначала удаляют.
- Публикация, закрытие и архивация — смена `status` одной версии.
- При публикации прежняя действующая версия закрывается на сервере, черновик становится действующим.
- Закрытие без новой версии выключает справочник для новых заявок. Дата конца вводится на экране.
- Архив — статус `archived`. Секция отсоединена, строки этой версии не ищутся.
- Даты на экранах — `ДД.ММ.ГГГГ`, в API — `ГГГГ-ММ-ДД`.
- Ошибки API показываются текстом из поля `message`.

### 1.1. Статусы версии

| API | Экран | Действия |
|---|---|---|
| `draft` | Черновик | Опубликовать, Удалить, Найти |
| `active` | Действует | Найти, Закрыть |
| `closed` | Закрыта | Найти, Архивировать |
| `archived` | В архиве | Нет |

## 2. Экран «Справочники»

### 2.1. Что отображается

| Колонка | Значение |
|---|---|
| Код | `dictionary_code` |
| Название | `dictionary_name` |
| Владелец | `owner` или «—» |
| Версия | `active_version_id` или «—», если действующей версии нет |

Если справочников нет, показывается «Справочников пока нет».

### 2.2. Действия

- Выбрать строку — открыть экран версий.
- «Создать новый справочник» — открыть форму нового справочника.
- «Загрузить ещё» — следующая страница, если API вернул `next_cursor`.

### 2.3. API

`GET /admin/passports`

| Параметр | Что передаётся |
|---|---|
| `limit` | Размер страницы, 1…1000 |
| `cursor` | Продолжение предыдущей страницы |

```json
{
  "items": [
    {
      "dictionary_id": "6b1f3c2a-1d4e-4a7b-9c31-0a5e8f2b7d10",
      "dictionary_code": "WallMaterial",
      "dictionary_name": "Материал стен",
      "owner": "Имущество",
      "status": "active",
      "active_version_id": 3
    }
  ],
  "next_cursor": null
}
```

## 3. Экран «Новый справочник»

### 3.1. Что отображается

| Поле | Обязательно | Что вводится |
|---|---|---|
| Название | да | `dictionary_name` |
| Код | да | `dictionary_code` |
| Владелец | нет | `owner` |

Таблица дополнительных полей:

| Колонка | Что вводится |
|---|---|
| Тип | Строка, целое, большое целое, дата, UUID |
| Поле | Код поля |
| Название | Подпись поля |

`value_code` и `name` в таблицу не добавляются. Они есть у каждой строки данных.

### 3.2. Действия

- «Добавить новое поле» — пустая строка.
- «Удалить» в строке — убрать поле до создания.
- «Создать» — создать паспорт и пустую таблицу, перейти к версиям.
- «Отмена» — вернуться к списку без сохранения.

### 3.3. API

`POST /admin/passports`

```json
{
  "dictionary_code": "WallMaterial",
  "dictionary_name": "Материал стен",
  "owner": "Имущество",
  "fields": [
    {
      "code": "parent_code",
      "name": "Родительский код",
      "type": "string",
      "length": 500,
      "nullable": true
    }
  ]
}
```

Ответ `201`: `dictionary_id`, `dictionary_code`, `dictionary_name`, `owner`, `status: "active"`, `table_name`, `schema_name: null`, `fields`, `versions: []`, `metadata_sql_path`. Версия при создании не появляется.

## 4. Экран «Версии справочника»

### 4.1. Что отображается

Шапка:

| Поле | Значение |
|---|---|
| Название | `dictionary_name` |
| Код | `dictionary_code` |
| Владелец | `owner` или «—» |

Таблица версий, по `version_id` по убыванию:

| Колонка | Значение |
|---|---|
| № версии | `version_id` |
| Статус | «Черновик», «Действует», «Закрыта», «В архиве» |
| Дата С | `valid_from` или «—» |
| Дата ПО | `valid_to` или «—» |
| Действия | по таблице статусов |

«В архиве» — это `status = archived`, не отдельный признак поверх `closed`.

### 4.2. Действия

- «Загрузить новую версию справочника» — диалог загрузки. Если черновик уже есть, кнопка не отправляет файл: на экране остаётся «Удалить» у черновика.
- «Опубликовать» — только черновик. `PATCH` со `status: "active"`. Черновик становится действующим, прежняя действующая версия закрывается. Дату конца вводит сервер.
- «Закрыть» — только действующая версия. Диалог с датой `valid_to`. Справочник перестаёт отдавать действующую версию новым заявкам. История по номеру и дате остаётся.
- «Архивировать» — только закрытая версия, после подтверждения. Статус становится `archived`, секция отсоединяется. Поиск строк этой версии больше недоступен.
- «Удалить» — только черновик, после подтверждения. Строка версии, секция и данные удаляются.
- «Найти» — экран поиска строк этой версии. Для архива действие скрыто.
- «Отмена» — вернуться к списку справочников.

### 4.3. API

`GET /admin/passports/{dictionary_code}` — шапка и описание полей. Строк значений нет.

`GET /admin/dictionaries/{dictionary_code}/versions` — таблица версий. Необязательный `status`: `draft`, `active`, `closed`, `archived`. Без него — все версии.

```json
{
  "items": [
    {
      "dictionary_version_id": "f3a8c1d2-6b44-4e90-8a17-2c5d9e0b7f31",
      "version_id": 4,
      "status": "draft",
      "valid_from": "2026-10-23",
      "valid_to": null,
      "archived": false
    }
  ]
}
```

`PATCH /admin/dictionaries/{dictionary_code}/versions/{version_id}`

| Действие | Тело |
|---|---|
| Опубликовать | `{ "status": "active" }` |
| Закрыть | `{ "status": "closed", "valid_to": "2026-12-31" }` |
| Архивировать | `{ "status": "archived" }` |

Ответ `200`. У публикации есть `closed_version_id` и `closed_valid_to`, если закрывать было кого.

`DELETE /admin/dictionaries/{dictionary_code}/versions/{version_id}` — удаление черновика. Ответ `204`. Для других статусов — `409`.

## 5. Диалог «Загрузка новой версии»

### 5.1. Что отображается

| Поле | Обязательно | Что вводится |
|---|---|---|
| Файл | да | CSV или JSON, не больше 100 МБ. Колонки `value_code`, `name` и поля справочника |
| Дата начала действия | да | `valid_from` |

### 5.2. Действия

- «Загрузить» — создать черновик.
- «Отмена» — закрыть диалог.
- После успеха диалог закрывается, список версий обновляется, у новой строки есть «Опубликовать» и «Удалить».
- Если черновик уже есть, показывается сообщение о конфликте. Новый черновик создаётся после «Удалить».

### 5.3. API

`POST /admin/dictionaries/{dictionary_code}`

`multipart/form-data`:

| Параметр | Что передаётся |
|---|---|
| `file` | CSV или JSON |
| `valid_from` | Дата начала действия, `ГГГГ-ММ-ДД` |

Ответ `201`: `dictionary_version_id`, `version_id`, `status: "draft"`, `valid_from`, `valid_to: null`, `row_count`, `data_sql_path`.

## 6. Экран «Данные версии»

Открывается действием «Найти» у черновика, действующей или закрытой версии.

### 6.1. Что отображается

Строка поиска и таблица найденных строк: `value_code`, `name` и дополнительные поля. Порядок по `value_code`.

Пустой поиск показывает страницу всех строк версии. «Загрузить ещё» — если есть `next_cursor`.

### 6.2. Действия

- Ввести текст и «Найти» — отфильтровать строки.
- «Очистить» — снова показать страницу без фильтра.
- «Назад» — вернуться к версиям.

### 6.3. API

`GET /admin/dictionaries/{dictionary_code}/versions/{version_id}`

| Параметр | Что передаётся |
|---|---|
| `query` | Подстрока в `value_code` или `name`, без учёта регистра. Можно не передавать |
| `limit` | 1…1000, по умолчанию 100 |
| `cursor` | Продолжение страницы |

Ответ `200`: `dictionary_code`, `version_id`, `version_status`, `valid_from`, `valid_to`, `items`, `next_cursor`. Для `archived` — `410`, экран не открывается.
