# Постановка: разбор файлов

Текст разделён на два модуля.

- [Интеграционный модуль](Постановка.%20интеграционный%20модуль.md) — отдельная подсистема. Запрос приходит из UI администратора или из Kafka. Модуль читает опубликованный файл и публикует одну из двух JSON-структур: метаданные таблиц либо содержимое таблиц.
- [Модуль импорта](Постановка.%20модуль%20импорта.md) — забирает из Kafka один или несколько таких JSON. По запросу собирает SQL создания таблиц нового справочника либо SQL заполнения новой секции существующего справочника.

Адреса файлов-примеров лежат в интеграционной постановке и в `Примеры справочников.md`.

Разбор файла и сборка секции разведены, между ними одна и та же пара JSON. Для четырёх источников из интеграционной постановки этого достаточно. До чтения через `service.api` не хватает каталога, транзакции и порядка пачек.

Интеграционный модуль знает XSD, CSV и ZIP. Импорт знает только таблицы, колонки и строки. Новый источник — новый разбор в первом модуле, второй не меняется. `version_id` в JSON источника нет, его приносит запрос на секцию. У простого списка суррогат появляется в SQL через `gen_random_uuid()`, у ГАР остаётся `object_id` из файла. Родитель ставится раньше ребёнка на разборе, импорт порядок не пересчитывает. ГАР читается потоком, в память целиком не берётся. Имена таблиц зафиксированы в постановке, а не выводятся из текста файла.

Дальше то, что этот конвейер сам не закрывает.

## Каталог

Файл в `db/sql-schema` или `db/sql-data` создаёт родителя или секцию и льёт строки. Строк `dictionary` и `dictionary_version` в нём нет. После `psql` таблицы есть, а `GET /dictionaries/AssBuilding/values/...` их не видит: сервис чтения ищет паспорт и версию в статусе `active`. Номер версии появляется так: паспорт при `create-tables`, черновик с этим `versionId` до `fill-section`, `active` и `valid_from` после успешного `psql`. Запись каталога раньше выполнения файла при сбое `psql` оставляет версию без секции.

## Транзакция и повтор

`psql -f` по умолчанию фиксирует каждый оператор. Обрыв на середине ГАР оставит занятую секцию `addr_obj_13`, повтор упрётся в уже существующую таблицу. Файл секции собирается как один `BEGIN` … `COMMIT`. Повтор того же `versionId` — отдельное решение: либо запретить, либо в начале файла снять только эту секцию.

## Порядок пачек

Импорт пишет SQL потоком и закрывает файл на `last: true`. Kafka сохраняет порядок только внутри одной партиции топика и одного ключа. Без ключа `loadId` пачка 3 может прийти раньше пачки 1, а `last` — раньше середины. Тогда внешний ключ ГАР не находит уровень, а файл уже закрыт. Ключ сообщения — `loadId`. Файл закрывается, когда есть непрерывный ряд `part` от 1 до N и у N стоит `last: true`.

## Типы на заливке

`DATE` и число без кавычек описаны в метаданных, а `fill-section` читает только топик данных, другим `loadId`. В строке JSON дата и код — оба строки. Импорт помнит метаданные этого `sourceCode` с момента `create-tables`. Поле `dictionaryCode` в запросе на файл не влияет: имена таблиц берутся из JSON. Чужой `loadId` соберёт чужую секцию без ошибки.

## Имя суррогата

В модели колонка называется по таблице: у `wall_material` это `wall_material_id`. В постановке импорта для всех простых списков записано `simple_dictionary_table_id`. На чтение по `value_code` это не влияет. Имя собирается из `tables[].name`, правило одно на все списки.

## Родитель ОКТМО

Поиск родителя ограничен тем же `section`. Поселение из раздела 2 (код на 11 знаков) не свяжется с муниципалитетом раздела 1, даже если код муниципалитета в файле есть. Для внешнего ключа внутри одной таблицы это безопасно. Иерархия «населённый пункт → муниципальное образование» при таком правиле не появится. Если она нужна, родитель ищется по коду в обоих разделах, а в ключе связи остаётся пара, которая реально есть в файле.

## ГАР по объёму

Контракт пачек по 1000 строк нормален для назначения здания и стен. Полный `AS_ADDR_OBJ` через JSON в Kafka и обратно в текст `INSERT` даст файл больше исходного XML, и `psql` будет вставлять его построчно. Состав из двух таблиц для проверки секций достаточен. На полном срезе те же метаданные, а тело секции — `COPY` из файла, который интеграционный модуль уже разложил потоком, без второй копии в виде JSON.
