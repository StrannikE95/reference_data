# Модуль справочников: интерфейс администратора

Экраны каталога, регистрации справочника, заливки черновика и публикации. 

Кэш, секции и строки значений на этих экранах не показываются. Содержимое справочника передаётся файлами, не полем формы. Большой файл пишется частями: на строке виден ход записи, оборванную запись можно продолжить.

## 1. Просмотр каталога

Экран показывает страницу паспортов: код, название, владелец, источник, статус, `table_name` или `schema_name`.
Выбор паспорта открывает его версии: `version_id`, статус, `valid_from`, `valid_to`. Незавершённая регистрация в этом списке не появляется.
С экрана открываются регистрация справочника, заливка версии выбранного паспорта и публикация его черновика.

## 2. Добавление профиля

Экран ведёт одну открытую регистрацию.
Сначала вводятся код, название, владелец и источник. После открытия регистрации код не меняется. Ошибочную регистрацию можно отменить: паспорт при этом не создаётся.
Дальше экран показывает файлы регистрации.

| Колонка   | Что в ней                        |
| --------- | -------------------------------- |
| Имя       | Имя файла                        |
| Размер    | Размер, переданный при выборе    |
| Состояние | `uploading`, `valid`, `invalid`  |
| Ошибка    | Текст для `invalid`, иначе пусто |

Пачка выбирается сразу несколькими файлами и добавляется к уже показанным. Пока идёт запись, строка остаётся `uploading`. После проверки она становится `valid` или `invalid`.
Файл в состоянии `invalid` или `valid` можно удалить. Исправленный файл загружается под тем же именем и занимает ту же строку. Отдельного поля для текста SQL нет.
Завершение регистрации доступно, когда есть хотя бы один файл и каждый файл `valid`. Пока есть `uploading` или `invalid`, завершение недоступно и видно, какой файл мешает.
После завершения экран показывает созданный паспорт: статус `active` и `table_name` либо `schema_name`. Версий у него ещё нет.

## 3. Добавление версии

Экран открывается для одного паспорта. Паспорт в статусе `inactive` версию не принимает.
Выбирается вид поставки. `increment` доступен только если профиль описывает дельту. Иначе выбор остаётся `full`, а причина показывается рядом.
Открытие создаёт черновик, если его ещё нет, и показывает его номер. Повторное открытие показывает тот же черновик и уже загруженные файлы.
Список файлов устроен так же, как у регистрации. Добавляются состояния `loading` и `loaded`.

| Состояние | Что делает экран |
|---|---|
| `uploading` | Показывает ход записи и даёт продолжить её |
| `invalid` | Показывает ошибку, даёт удалить файл и загрузить исправленный под тем же именем |
| `valid` | Даёт удалить файл до заливки |
| `loading` | Показывает, что таблица этого файла ещё заполняется. Удаление и отмена черновика в этот момент недоступны |
| `loaded` | Показывает, что строки уже в черновике. Удаление очищает только таблицу этого файла |

Завершение заливки доступно, когда каждый уже принятый файл `valid` и на каждую таблицу профиля есть файл. Экран называет недостающие таблицы. После запуска список обновляется: файлы переходят в `loading`, затем в `loaded` или обратно в `invalid`. Уже залитые таблицы при ошибке соседнего файла остаются `loaded`. Повторное завершение нужно только для файлов, которые снова стали `valid`.

Отмена черновика удаляет его номер, секции и файлы. Пока какой-либо файл `loading`, отмена недоступна. Сервис чтения с этого экрана не вызывается.

## 4. Активация версии

Экран открывается для черновика выбранного паспорта. На нём видны номер черновика, вид поставки и то, что публикация сделает с действующей версией: её номер и `valid_to` на день раньше введённой даты. Для первой версии прежней действующей нет.

Вводится `valid_from`. Публикация доступна, когда дата заполнена и каждый файл черновика `loaded`. Иначе экран показывает, какой файл ещё не залит.

После публикации экран показывает новый статус `active`, `valid_from` и, если прежняя версия была, её `closed` и `valid_to`. Отдельных переключателей статуса нет.
