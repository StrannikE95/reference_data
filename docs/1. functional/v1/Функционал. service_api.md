# Модуль справочников: контракт чтения


## 1. Что читается

Контракт отдаёт строку простого списка: `value_code` и `name` одной опубликованной версии. Набор таблиц (`schema_name`) им не читается: отдельного вида «код — наименование» у набора нет.
Черновик не возвращается. Неизвестный код не заменяется другим. Колонки сверх каркаса `value_code` и `name` в ответ не входят; фильтр по коду связанного справочника тоже. Пока их нет, отбор из границ модуля фасад делает по уже полученной странице.
Дата в запросе — календарный день `YYYY-MM-DD`, без времени суток. Повтор запроса не меняет данные. Неактивный справочник читается: новые версии он не публикует, уже выпущенные остаются.
Редакцию выбирает один признак. `on_date` и `version_id` вместе не передаются.

| Что передано | Какая редакция |
|---|---|
| ничего | Действующая. Если её нет, текущей редакции нет |
| `on_date` | Версия, в чей период день попадает включительно. Пустой `valid_to` — открытый конец. День вне всех периодов на более позднюю версию не переносится |
| `version_id` | Эта действующая или закрытая версия |

## 2. Операции

### 2.1. Одно значение

`GET /dictionaries/{dictionary_code}/values/{value_code}`

Параметры запроса: `on_date` или `version_id`, либо ни одного.
Ответ описывает выбранную редакцию и запрошенный код. Подпись есть только при `result = present`.

```json
{
  "dictionary_code": "WallMaterial",
  "version_id": 2,
  "version_status": "active",
  "valid_from": "2026-10-20",
  "valid_to": null,
  "archived": false,
  "result": "present",
  "value_code": "BRICK",
  "name": "Кирпич"
}
```

### 2.2. Страница редакции

`GET /dictionaries/{dictionary_code}/values`

Параметры запроса: тот же выбор редакции, затем `limit` и `cursor`.
Страница упорядочена по `value_code`. `limit` обязателен, если строк может быть больше одной страницы; допустимы значения от 1 до 1000. Без `limit` модуль отдаёт не больше 1000 строк. `cursor` непрозрачен и продолжает ту же редакцию: вместе с ним передаётся тот же признак выбора версии, что и в первом запросе. Конец списка — пустой `next_cursor`.

```json
{
  "dictionary_code": "WallMaterial",
  "version_id": 2,
  "version_status": "active",
  "valid_from": "2026-10-20",
  "valid_to": null,
  "archived": false,
  "items": [
    { "value_code": "BRICK", "name": "Кирпич" }
  ],
  "next_cursor": null
}
```

### 2.3. Проверка ссылок

`POST /dictionaries/{dictionary_code}/values/check`

Тело запроса — номер уже сохранённой версии и список кодов. Даты здесь нет: проверка смотрит секцию переданного `version_id`. Запрос ничего не записывает. Кодов в одном запросе — от 1 до 1000, повтор одного кода возвращается один раз. Чужой код в списке не отменяет остальные.

```json
{
  "version_id": 2,
  "value_codes": ["BRICK", "PAPER"]
}
```

```json
{
  "dictionary_code": "WallMaterial",
  "version_id": 2,
  "version_status": "active",
  "valid_from": "2026-10-20",
  "valid_to": null,
  "archived": false,
  "items": [
    { "value_code": "BRICK", "result": "present", "name": "Кирпич" },
    { "value_code": "PAPER", "result": "absent", "name": null }
  ]
}
```

## 3. Результат по строке

| `result` | Что это | Что делает вызвавший |
|---|---|---|
| `present` | Код есть в секции этой версии | Можно сохранить ссылку: код справочника, код значения, `version_id` из ответа |
| `absent` | Редакция на месте, кода в ней нет | Ссылку не сохраняют и другой код вместо него не берут |
| `archived` | Строка каталога есть, секция отсоединена | По этой секции код ни подтвердить, ни опровергнуть. Для уже выпущенного документа остаётся копия значений у потребителя |

У страницы `archived: true` означает то же, что `result = archived` у одной строки: `items` пуст.
`version_id` в ответе — номер, который модуль фактически прочитал. Его сохраняют вместе с выбранным значением. Клиент свой счётчик версий не ведёт.

## 4. Когда редакции нет

Это ошибки запроса, а не пустой список. Пустая страница не означает «справочник без действующей версии».

| Ситуация | `error` |
|---|---|
| Нет справочника с таким кодом | `dictionary_not_found` |
| Переданы и `on_date`, и `version_id` | `version_selector_conflict` |
| `version_id` у этого справочника не найден | `version_not_found` |
| `version_id` указывает на черновик | `version_not_published` |
| Нет действующей версии, а дата и номер не переданы | `no_active_version` |
| День не попадает ни в один период | `date_out_of_range` |
| `cursor` от другой редакции, `limit` вне 1…1000, в проверке нет кодов или их больше 1000 | `invalid_request` |

```json
{
  "error": "date_out_of_range",
  "dictionary_code": "WallMaterial",
  "on_date": "2023-12-31"
}
```

## 5. Пример

У `WallMaterial` версия 1 действует с 1 января 2024 и закрыта по 19 октября 2026. Версия 2 действует с 20 октября 2026, `valid_to` пуст. В обеих есть `BRICK`.

- `GET .../values/BRICK` возвращает версию 2 и `result = present`.
- `GET .../values/BRICK?on_date=2024-06-01` возвращает версию 1.
- `GET .../values/BRICK?on_date=2023-12-31` возвращает `date_out_of_range`. Версия 1 не подставляется.
- `GET .../values?on_date=2024-06-01` возвращает страницу версии 1.
- `POST .../values/check` с `version_id = 2` и кодами `BRICK`, `PAPER`: у первого `present`, у второго `absent`.

После отсоединения секции версии 1 чтение `version_id = 1` возвращает даты из каталога, `archived: true` и не отдаёт строк.
