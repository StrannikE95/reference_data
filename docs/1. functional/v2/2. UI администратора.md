# UI администратора (v2)

Общее описание экранов администратора справочников. UI работает с простыми списками: у справочника одна таблица данных и версии этой таблицы.

## 1. Общие правила

- Справочник описывается полями «Код», «Название» и «Владелец».
- Владелец вводится и редактируется в форме справочника, отображается в списке и на экране версий.
- Код и название справочника после создания не редактируются.
- Версия создаётся загрузкой файла в статусе «Черновик».
- Публикация — отдельное действие. Только после публикации версия становится действующей.
- При публикации прежняя действующая версия закрывается, а черновик становится действующей версией.
- Даты на экранах отображаются как `ДД.ММ.ГГГГ`, в API передаются как `ГГГГ-ММ-ДД`.

### 1.1. Статусы версии

| API | Экран | Действия |
|---|---|---|
| `draft` | Черновик | Опубликовать |
| `active` | Действует | Скачать |
| `closed` | Закрыта | Скачать, Архивировать |
| `closed` + `archived: true` | В архиве | Нет |

## 2. Экран «Справочники»

### 2.1. Что отображается

Таблица справочников:

| Колонка | Значение |
|---|---|
| Код | `dictionary_code` |
| Название | `dictionary_name` |
| Владелец | `owner` или «—» |
| Версия | `active_version_id` или «—», если действующей версии нет |

Если справочников нет, показывается «Справочников пока нет».

### 2.2. Действия

- Выбрать строку — открыть экран версий справочника.
- «Создать новый справочник» — открыть форму нового справочника.
- «Загрузить ещё» — добавить следующую страницу, если API вернул `next_cursor`.

### 2.3. API

`GET /admin/dictionaries`

Параметры:

| Параметр | Что передаётся |
|---|---|
| `limit` | Размер страницы, 1…1000 |
| `cursor` | Продолжение предыдущей страницы |

Ответ:

```json
{
  "items": [
    {
      "dictionary_id": "6b1f3c2a-1d4e-4a7b-9c31-0a5e8f2b7d10",
      "dictionary_code": "WallMaterial",
      "dictionary_name": "Материал стен",
      "owner": "Имущество",
      "active_version_id": 3
    }
  ],
  "next_cursor": null
}
```

## 3. Экран «Новый справочник»

### 3.1. Что отображается

Поля справочника:

| Поле | Обязательно | Что вводится |
|---|---|---|
| Название | да | `dictionary_name` |
| Код | да | `dictionary_code` |
| Владелец | нет | `owner` |

Таблица дополнительных полей:

| Колонка | Что вводится |
|---|---|
| Тип | Тип поля: строка, целое, большое целое, дата, UUID |
| Поле | Код поля |
| Название | Подпись поля |

Базовые поля `value_code` и `name` в таблицу не добавляются.

### 3.2. Действия

- «Добавить новое поле» — добавить пустую строку.
- «Удалить» в строке — удалить дополнительное поле до создания справочника.
- «Создать» — создать справочник и перейти к его версиям.
- «Отмена» — вернуться к списку без сохранения.

### 3.3. API

`POST /admin/dictionaries`

Тело:

```json
{
  "dictionary_code": "WallMaterial",
  "dictionary_name": "Материал стен",
  "owner": "Имущество",
  "fields": [
    {
      "code": "parent_code",
      "name": "Родительский код",
      "type": "string",
      "length": 500,
      "nullable": true
    }
  ]
}
```

Ответ — созданный справочник: `dictionary_id`, `dictionary_code`, `dictionary_name`, `owner`, `fields`, `versions: []`.

## 4. Экран «Версии справочника»

### 4.1. Что отображается

Шапка справочника:

| Поле | Значение |
|---|---|
| Название | `dictionary_name` |
| Код | `dictionary_code` |
| Владелец | `owner` или «—» |

Таблица версий:

| Колонка | Значение |
|---|---|
| № версии | `version_id` |
| Статус | «Черновик», «Действует», «Закрыта» или «В архиве» |
| Дата С | `valid_from` или «—» |
| Дата ПО | `valid_to` или «—» |
| Действия | «Опубликовать», «Скачать», «Архивировать» |

Версии упорядочены по `version_id` по убыванию.

### 4.2. Действия

- «Загрузить новую версию справочника» — открыть диалог загрузки, выбор и отправка на сервер файла. TODO: фаайл в формате Excel
- «Опубликовать» — доступно для черновика. После публикации черновик становится действующей версией, прежняя действующая версия закрывается.
- «Скачать» — доступно для действующей и закрытой версии. Скачивается JSON-файл версии. TODO: Скачивается в формате Excel
- «Архивировать» — доступно для закрытой неархивированной версии. Перед архивацией показывается подтверждение.
- «Отмена» — вернуться к списку справочников.

### 4.3. API

`GET /admin/dictionaries/{dictionary_code}`

Параметр пути — код справочника. Ответ — паспорт справочника, описание полей и список версий:

```json
{
  "dictionary_code": "WallMaterial",
  "dictionary_name": "Материал стен",
  "owner": "Имущество",
  "fields": [],
  "versions": [
    {
      "version_id": 4,
      "status": "draft",
      "valid_from": "2026-10-23",
      "valid_to": null,
      "archived": false
    }
  ]
}
```

`POST /admin/dictionaries/{dictionary_code}/versions/{version_id}/publish`

Параметры пути — код справочника и номер версии. Тела нет. Ответ — опубликованная версия: `version_id`, `status: "active"`, `valid_from`, `valid_to: null`.

`GET /admin/dictionaries/{dictionary_code}/versions/{version_id}/download`

Параметры пути — код справочника и номер версии. Ответ — JSON-файл с описанием полей и строками версии.

`POST /admin/dictionaries/{dictionary_code}/versions/{version_id}/archive`

Параметры пути — код справочника и номер версии. Тела нет. Ответ `204` без тела.

## 5. Диалог «Загрузка новой версии»

### 5.1. Что отображается

| Поле | Обязательно | Что вводится |
|---|---|---|
| Файл | да | CSV или JSON с данными |
| Дата начала действия | да | `valid_from` |

### 5.2. Действия

- «Загрузить» — загрузить файл и создать черновик версии.
- «Отмена» — закрыть диалог.
- После успешной загрузки диалог закрывается, таблица версий обновляется, у новой строки появляется действие «Опубликовать».

### 5.3. API

`POST /admin/dictionaries/{dictionary_code}/versions`

`multipart/form-data`:

| Параметр | Что передаётся |
|---|---|
| `file` | CSV или JSON |
| `valid_from` | Дата начала действия |

Ответ `201`:

```json
{
  "dictionary_version_id": "f3a8c1d2-6b44-4e90-8a17-2c5d9e0b7f31",
  "version_id": 4,
  "status": "draft",
  "valid_from": "2026-10-23",
  "valid_to": null,
  "row_count": 2,
  "data_sql_path": "db/sql-data/wall_material/2026.10.23 16.10.00 - wall_material.sql"
}
```
