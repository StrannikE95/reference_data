# UI администратора (v2)

Описание экранов администратора справочников. Схема соответствует `Справочники 2.drawio`: список справочников, форма нового справочника, экран версий, загрузка, скачивание и архивация.

## 1. Общие правила

- Администратор работает с простыми списками: у справочника одна таблица данных.
- Паспорт справочника после создания не редактируется.
- Отдельной публикации нет: успешно загруженная версия сразу становится действующей.
- Черновик — техническое состояние на время загрузки. Постоянного экрана черновика нет.
- Владелец и источник в v2 не редактируются и на экранах не показываются.
- Удаление справочника и версии в v2 не предусмотрено.
- Все даты отображаются как `ДД.ММ.ГГГГ`, в API передаются как `ГГГГ-ММ-ДД`.
- Ошибки API показываются текстом из `message`; поле `error` используется для выбора реакции.

### 1.1. Статусы версии

| API | Экран | Цвет |
|---|---|---|
| `draft` | Черновик | серый |
| `active` | Действует | зелёный |
| `closed` | Закрыта | серый |
| `closed` + `archived: true` | В архиве | тёмно-серый |

### 1.2. Навигация

```text
Список справочников
  ├─ Создать новый справочник → Форма нового справочника
  └─ Выбрать справочник → Версии справочника
       ├─ Загрузить новую версию → Диалог загрузки
       ├─ Скачать версию
       └─ Архивировать версию → Подтверждение
```

## 2. Экран «Справочники»

### 2.1. Назначение

Показывает страницу справочников и даёт перейти к созданию или к версиям выбранного справочника.

### 2.2. Состав

| Элемент | Описание |
|---|---|
| Заголовок | «Справочники» |
| Таблица | Колонки «Код», «Название», «Версия» |
| Кнопка | «Создать новый справочник» |
| Кнопка | «Загрузить ещё», если есть `next_cursor` |

Строка таблицы:

| Колонка | Значение |
|---|---|
| Код | `dictionary_code` |
| Название | `dictionary_name` |
| Версия | `active_version_id` или «—», если действующей версии нет |

Владелец, источник и статус паспорта на экране не показываются.

### 2.3. Поведение

- Клик по строке открывает экран версий этого справочника.
- «Создать новый справочник» открывает форму.
- «Загрузить ещё» добавляет следующую страницу к текущей таблице.
- Список запрашивается через `GET /admin/dictionaries`.
- Пока страница загружается, показывается индикатор; таблица не очищается.
- Если справочников нет, показывается «Справочников пока нет» и кнопка создания.
- Если запрос завершился ошибкой, показывается баннер с текстом и кнопкой «Повторить».

### 2.4. Ограничения

- Поиска и фильтров в v2 нет.
- Сортировка фиксирована по коду.
- Массовых действий нет.

## 3. Экран «Поля нового Справочника»

### 3.1. Назначение

Создаёт паспорт справочника и описание его дополнительных полей. После создания сервер создаёт SQL-файл метаданных и физическую таблицу.

### 3.2. Состав

| Элемент | Обязателен | Описание |
|---|---|---|
| «Название» | да | `dictionary_name`, до 200 символов |
| «Код» | да | `dictionary_code`, латиница, цифры и `_`, до 63 символов |
| Таблица полей | нет | Колонки «Тип», «Поле», «Название» |
| «Добавить новое поле» | — | Добавляет пустую строку в таблицу полей |
| «Создать» | — | Создаёт справочник |
| «Отмена» | — | Возвращает к списку без создания |

Таблица полей:

| Колонка | Что вводится | Пример |
|---|---|---|
| Тип | Тип поля | Строка |
| Поле | Код поля | `parent_code` |
| Название | Подпись поля | `Родительский код` |

Типы:

| Тип | API | Хранение |
|---|---|---|
| Строка | `string` | `varchar(500)` |
| Целое | `integer` | `integer` |
| Большое целое | `bigint` | `bigint` |
| Дата | `date` | `date` |
| UUID | `uuid` | `uuid` |

Базовые поля `value_code` и `name` в таблицу не добавляются: они есть у каждого справочника.

### 3.3. Поведение

- Новая строка поля добавляется пустой; тип по умолчанию — «Строка».
- Строку поля можно удалить до создания справочника.
- «Создать» активна, когда заполнены название и код, а все добавленные строки полей заполнены.
- Пока идёт создание, кнопка показывает индикатор и повторное нажатие невозможно.
- После успеха открывается экран версий нового справочника. Версий пока нет.
- «Отмена» возвращает к списку; введённые данные не сохраняются.
- Если справочник с таким кодом уже есть, ошибка показывается у поля «Код».
- Если сервер вернул ошибку создания таблицы, показывается баннер; форма остаётся заполненной.

### 3.4. Проверки

| Поле | Проверка | Текст |
|---|---|---|
| Название | не пусто, до 200 | «Укажите название» |
| Код | `^[A-Za-z][A-Za-z0-9_]{0,62}$` | «Код: латиница, цифры и _, начиная с буквы» |
| Код | уникален | «Справочник с таким кодом уже есть» |
| Поле | `^[a-z][a-z0-9_]{0,62}$` | «Код поля: строчная латиница, цифры и _» |
| Поле | не `version_id`, `value_code`, `name` | «Это имя занято базовой колонкой» |
| Поле | уникально в форме | «Код поля повторяется» |
| Название поля | не пусто, до 200 | «Укажите название поля» |
| Тип | выбран | «Выберите тип» |

Дополнительные поля создаются nullable. Длина строки — 500 символов. Отдельных полей для длины и обязательности в v2 нет.

### 3.5. API

`POST /admin/dictionaries`

Тело собирается из полей формы:

```json
{
  "dictionary_code": "WallMaterial",
  "dictionary_name": "Материал стен",
  "fields": [
    {
      "code": "parent_code",
      "name": "Родительский код",
      "type": "string",
      "length": 500,
      "nullable": true
    }
  ]
}
```

## 4. Экран «Версии справочника»

### 4.1. Назначение

Показывает версии выбранного справочника, даёт загрузить новую версию, скачать существующую и архивировать закрытую.

### 4.2. Состав

| Элемент | Описание |
|---|---|
| Заголовок | «Версии справочника» |
| Название | `dictionary_name`, только чтение |
| Код | `dictionary_code`, только чтение |
| Таблица версий | Колонки «№ версии», «Статус», «Дата С», «Дата ПО», действия |
| Кнопка | «Загрузить новую версию справочника» |
| Кнопка | «Отмена» — возврат к списку |

Строка таблицы:

| Колонка | Значение |
|---|---|
| № версии | `version_id` |
| Статус | «Черновик», «Действует», «Закрыта» или «В архиве» |
| Дата С | `valid_from` или «—» |
| Дата ПО | `valid_to` или «—» |
| Действия | «Скачать», «Архивировать» |

Порядок строк — по `version_id` по убыванию.

### 4.3. Действия

#### Скачать

- Доступно для действующей и закрытой версии.
- Недоступно для черновика и архивированной версии.
- Вызывает `GET /admin/dictionaries/{dictionary_code}/versions/{version_id}/download`.
- Браузер скачивает JSON-файл `{dictionary_code}_v{version_id}.json`.
- Если версия уже архивирована, показывается «Данные версии в архиве» и строка обновляется.

#### Архивировать

- Доступно только для закрытой неархивированной версии.
- Перед вызовом показывается подтверждение:

```text
Архивировать версию 2?
Данные версии будут отсоединены от таблицы справочника.
Строка каталога и история версии сохранятся, но скачивание станет недоступно.
```

- Вызывает `POST /admin/dictionaries/{dictionary_code}/versions/{version_id}/archive`.
- После успеха статус меняется на «В архиве», кнопки «Скачать» и «Архивировать» становятся недоступны.
- Повторная архивация не предлагается.

#### Загрузить новую версию

- Открывает диалог загрузки.
- Доступно всегда, независимо от наличия версий.

### 4.4. Состояния экрана

| Состояние | Что видно |
|---|---|
| Загрузка | Индикатор; заголовок и код уже показаны |
| Нет версий | «Версий пока нет» и кнопка загрузки |
| Есть версии | Таблица версий |
| Ошибка чтения | Баннер и кнопка «Повторить» |
| Идёт загрузка | Кнопка загрузки недоступна; в таблице локальная строка «Черновик» |
| Идёт архивация | Действия строки недоступны |

### 4.5. API

- `GET /admin/dictionaries/{dictionary_code}` — паспорт и версии.
- `GET /admin/dictionaries/{dictionary_code}/versions/{version_id}/download` — скачивание.
- `POST /admin/dictionaries/{dictionary_code}/versions/{version_id}/archive` — архивация.

## 5. Диалог «Загрузка новой версии»

### 5.1. Назначение

Загружает файл данных и создаёт новую действующую версию. Диалог открывается кнопкой «Загрузить новую версию справочника».

### 5.2. Состав

| Элемент | Обязателен | Описание |
|---|---|---|
| Файл | да | CSV или JSON, до 100 МБ |
| Дата начала действия | да | `valid_from`, по умолчанию сегодня |
| «Загрузить» | — | Запускает загрузку |
| «Отмена» | — | Закрывает диалог |

### 5.3. Проверки

| Поле | Проверка | Текст |
|---|---|---|
| Файл | выбран | «Выберите файл» |
| Файл | расширение `.csv` или `.json` | «Поддерживаются CSV и JSON» |
| Файл | размер до 100 МБ | «Файл больше 100 МБ» |
| Дата | заполнена | «Укажите дату начала действия» |
| Дата | позже `valid_from` действующей версии | «Дата должна быть позже начала действующей версии» |

Если действующей версии нет, ограничение на дату только формальное.

### 5.4. Поведение

- «Загрузить» недоступна, пока файл не выбран или дата не заполнена.
- Пока идёт запрос, кнопки и поля недоступны, показывается индикатор.
- Успех: диалог закрывается, таблица версий перечитывается, новая строка подсвечивается.
- Новая версия получает статус «Действует»; прежняя действующая становится «Закрыта» с датой «по» на день раньше.
- Ошибка: диалог остаётся открытым, показывается сообщение; файл и дата сохраняются для повтора.
- Если сервер вернул `duplicate_value_code`, в сообщении показываются повторяющиеся коды.
- Если сервер вернул `invalid_value`, показываются строка и поле.
- Если сервер вернул `script_failed`, показывается общий текст ошибки; диалог можно закрыть.
- Отмена во время запроса недоступна: запрос уже отправлен.

### 5.5. API

`POST /admin/dictionaries/{dictionary_code}/versions`

`multipart/form-data`:

| Поле | Значение |
|---|---|
| `file` | Выбранный CSV или JSON |
| `valid_from` | Дата из поля |

Успех — `201` с номером версии, статусом `active`, датой, количеством строк и номером закрытой версии.

## 6. Ошибки и уведомления

### 6.1. Где показывать

| Ошибка | Место |
|---|---|
| Ошибка поля формы | Под полем |
| Дублирование кода справочника | Под полем «Код» |
| Ошибка файла | В диалоге загрузки |
| Ошибка строки данных | В диалоге, с номером строки и полем |
| Ошибка SQL | Баннер в диалоге или на экране |
| Ошибка чтения списка | Баннер на экране |
| Успешное создание | Переход на экран версий |
| Успешная загрузка | Сообщение и обновление таблицы |
| Успешная архивация | Обновление строки |

### 6.2. Тексты

- `dictionary_already_exists` — «Справочник с таким кодом уже есть».
- `invalid_valid_from` — «Дата должна быть позже начала действующей версии».
- `unsupported_media_type` — «Поддерживаются только CSV и JSON».
- `file_too_large` — «Файл больше 100 МБ».
- `empty_file` — «Файл пуст».
- `invalid_file` — «Не удалось разобрать файл».
- `unknown_field` — «В файле есть колонка, которой нет в справочнике».
- `missing_field` — «В файле нет обязательной колонки».
- `duplicate_value_code` — «В файле повторяется код значения».
- `invalid_value` — «Значение не соответствует типу поля».
- `script_failed` — «Не удалось выполнить SQL. Обратитесь к администратору».
- `version_archived` — «Данные версии в архиве».
- `version_not_closed` — «Архивировать можно только закрытую версию».

---

## 7. Ограничения v2

- Нет редактирования паспорта и полей после создания.
- Нет удаления справочника.
- Нет отдельной публикации и выбора черновика.
- Нет поиска, фильтров и сортировки по колонкам.
- Нет истории действий администратора.
- Нет управления ролями и доступами: предполагается, что администратор уже авторизован.
