# Контракты API (v2)

Описание внешних HTTP-контрактов административного и сервисного контуров. Контракты соответствуют схеме `Справочники 2.drawio`: список справочников, создание справочника, версии, загрузка, скачивание и архивация. Внутренние вызовы между модулями публичным API не являются и здесь не описаны.

## 1. Общие правила

### 1.1. Адреса

- Административный контур: `/admin/...`.
- Сервисный контур чтения: `/dictionaries/...`.

### 1.2. Формат

- Тела запросов и ответов — JSON UTF-8, кроме загрузки файла.
- `Content-Type: application/json; charset=utf-8`.
- Идентификаторы — UUID в нижнем регистре.
- Даты — календарный день `YYYY-MM-DD`, без времени и часового пояса.
- Денежные, дробные и произвольные типы в v2 не используются.
- Неизвестные поля в JSON-запросе отклоняются с `invalid_request`.

### 1.3. Ошибки

Ошибка — JSON-объект:

```json
{
  "error": "invalid_value",
  "message": "Строка 12, поле start_date: ожидается дата YYYY-MM-DD",
  "details": {
    "row": 12,
    "field": "start_date"
  }
}
```

- `error` — стабильный машинный код.
- `message` — текст для администратора.
- `details` — объект или массив с уточнением; может отсутствовать.

HTTP-коды:

| Код | Когда |
|---|---|
| `200` | Успешное чтение или изменение без создания |
| `201` | Создан справочник или версия |
| `204` | Команда выполнена, тела нет |
| `400` | Некорректный запрос |
| `404` | Объект не найден |
| `409` | Конфликт состояния |
| `410` | Версия архивирована, данные недоступны |
| `413` | Файл больше допустимого |
| `415` | Неподдерживаемый формат файла |
| `422` | Файл или данные не прошли проверку |
| `500` | Ошибка выполнения SQL или внутренняя ошибка |

### 1.4. Пагинация

Списки используют `limit` и `cursor`.

- `limit` — от 1 до 1000. По умолчанию 100.
- `cursor` — непрозрачная строка, которую вернул предыдущий ответ.
- `next_cursor` — `null`, если страниц больше нет.
- `cursor` нельзя разбирать или собирать на клиенте.
- Порядок списка фиксирован: справочники — по `dictionary_code`, значения — по `value_code`.

### 1.5. Идемпотентность

- `GET` не меняет данные.
- `POST /admin/dictionaries` не идемпотентен: повтор с тем же кодом возвращает `409`.
- `POST .../versions` не идемпотентен: каждый успешный вызов создаёт новую версию.
- `POST .../archive` идемпотентен: повторная архивация уже архивированной версии возвращает `204`.

### 1.6. Полномочия

Проверка аутентификации и полномочий администратора выполняется внешней подсистемой ИБ. API не содержит экранов входа и не управляет ролями.

## 2. Административный API

### 2.1. Список справочников

`GET /admin/dictionaries`

Параметры:

| Параметр | Тип | Обязателен | Описание |
|---|---|---|---|
| `limit` | integer | нет | Размер страницы, 1…1000, по умолчанию 100 |
| `cursor` | string | нет | Продолжение предыдущей страницы |

Ответ `200`:

```json
{
  "items": [
    {
      "dictionary_id": "6b1f3c2a-1d4e-4a7b-9c31-0a5e8f2b7d10",
      "dictionary_code": "WallMaterial",
      "dictionary_name": "Материал стен",
      "owner": "Имущество",
      "source": "Ведомственный перечень",
      "status": "active",
      "active_version_id": 3
    },
    {
      "dictionary_id": "1d9e6a42-5c77-4f18-9b02-7a3d1e5c8f21",
      "dictionary_code": "OwnershipType",
      "dictionary_name": "Вид собственности",
      "owner": null,
      "source": null,
      "status": "active",
      "active_version_id": null
    }
  ],
  "next_cursor": null
}
```

Правила:

- `active_version_id` — номер действующей версии или `null`, если действующей версии нет.
- `owner` и `source` могут быть `null`; форма v2 их не заполняет.
- `status` — статус паспорта: `active` или `inactive`. В v2 паспорт создаётся в `active`; отдельной операции изменения статуса нет.
- Незавершённая загрузка версии в список не попадает.

Ошибки: `invalid_request` при `limit` вне диапазона или неразборчивом `cursor`.

### 2.2. Паспорт и версии

`GET /admin/dictionaries/{dictionary_code}`

Ответ `200`:

```json
{
  "dictionary_id": "6b1f3c2a-1d4e-4a7b-9c31-0a5e8f2b7d10",
  "dictionary_code": "WallMaterial",
  "dictionary_name": "Материал стен",
  "owner": "Имущество",
  "source": "Ведомственный перечень",
  "status": "active",
  "table_name": "wall_material",
  "schema_name": null,
  "fields": [
    {
      "code": "parent_code",
      "name": "Родительский код",
      "type": "string",
      "length": 500,
      "nullable": true
    }
  ],
  "versions": [
    {
      "dictionary_version_id": "c2a91e40-7b55-4d1a-8e66-15f0c9a4b812",
      "version_id": 3,
      "status": "active",
      "valid_from": "2026-10-23",
      "valid_to": null,
      "archived": false
    },
    {
      "dictionary_version_id": "e84b0d17-2f6c-4c9a-b331-90ad6e5f4412",
      "version_id": 2,
      "status": "closed",
      "valid_from": "2026-01-01",
      "valid_to": "2026-10-22",
      "archived": false
    }
  ]
}
```

Правила:

- `versions` отсортированы по `version_id` по убыванию.
- `valid_from` у черновика может быть `null`; у действующей и закрытой версии заполнен.
- `valid_to` заполнен только у закрытой версии.
- `archived` — вычисляемый признак: секция версии отсоединена.
- `fields` — неизменяемое описание полей справочника.
- `table_name` заполнен для простого списка; `schema_name` — `null`.
- `schema_name` зарезервирован для наборов таблиц, но API v2 наборы не создаёт.

Ошибки: `dictionary_not_found`.

### 2.3. Создание справочника

`POST /admin/dictionaries`

Создаёт паспорт, описание полей, SQL-файл метаданных и физическую таблицу. Версия при создании не создаётся.

Тело:

```json
{
  "dictionary_code": "WallMaterial",
  "dictionary_name": "Материал стен",
  "owner": "Имущество",
  "source": "Ведомственный перечень",
  "fields": [
    {
      "code": "parent_code",
      "name": "Родительский код",
      "type": "string",
      "length": 500,
      "nullable": true
    }
  ]
}
```

Поля:

| Поле | Тип | Обязательно | Правила |
|---|---|---|---|
| `dictionary_code` | string | да | `^[A-Za-z][A-Za-z0-9_]{0,62}$`, уникален без учёта регистра, до 63 символов |
| `dictionary_name` | string | да | 1…200 символов |
| `owner` | string | нет | до 200 символов; по умолчанию `null` |
| `source` | string | нет | до 200 символов; по умолчанию `null` |
| `fields` | array | нет | до 50 дополнительных полей |

Поле `fields[]`:

| Поле | Тип | Обязательно | Правила |
|---|---|---|---|
| `code` | string | да | `^[a-z][a-z0-9_]{0,62}$`, уникален, не `version_id`, `value_code`, `name` |
| `name` | string | да | 1…200 символов |
| `type` | string | да | `string`, `integer`, `bigint`, `date`, `uuid` |
| `length` | integer | для `string` | 1…4000; по умолчанию 500 |
| `nullable` | boolean | нет | по умолчанию `true` |

Правила создания:

- `dictionary_code` после создания не меняется.
- `WallMaterial` преобразуется в имя таблицы `wall_material`.
- Имя таблицы после преобразования — не длиннее 63 символов.
- Базовые колонки `value_code` и `name` добавляются всегда и не описываются в `fields`.
- Дополнительные поля с типом `string` получают `varchar(length)`.
- Одинаковые `code` в `fields` недопустимы.
- `owner` и `source` форма v2 не заполняет; они могут быть `null`.
- Операция атомарна: если создать таблицу или записать SQL-файл не удалось, паспорт не сохраняется.

Ответ `201`:

```json
{
  "dictionary_id": "6b1f3c2a-1d4e-4a7b-9c31-0a5e8f2b7d10",
  "dictionary_code": "WallMaterial",
  "dictionary_name": "Материал стен",
  "owner": "Имущество",
  "source": "Ведомственный перечень",
  "status": "active",
  "table_name": "wall_material",
  "schema_name": null,
  "fields": [
    {
      "code": "parent_code",
      "name": "Родительский код",
      "type": "string",
      "length": 500,
      "nullable": true
    }
  ],
  "versions": [],
  "metadata_sql_path": "db/sql-schema/2026.10.23 16.00.00 - wall_material.sql"
}
```

Ошибки:

- `dictionary_already_exists` — код уже занят.
- `invalid_request` — неверный код, имя, тип поля или состав `fields`.
- `script_failed` — SQL создания таблицы не выполнен.

### 2.4. Загрузка новой версии

`POST /admin/dictionaries/{dictionary_code}/versions`

`Content-Type: multipart/form-data`

Форма:

| Поле | Тип | Обязательно | Описание |
|---|---|---|---|
| `file` | file | да | CSV или JSON с данными |
| `valid_from` | string | да | Дата начала действия, `YYYY-MM-DD` |

Форматы файла:

- CSV: UTF-8, первая строка — заголовок, разделитель `;` или `,`, кавычки `"`, удвоение кавычки `""`.
- JSON: массив объектов или объект с полем `rows`.
- Обязательные колонки/ключи: `value_code`, `name`.
- Дополнительные колонки/ключи должны совпадать с `fields` справочника.
- Пустые значения допустимы только для nullable-полей.
- Максимальный размер файла — 100 МБ.

Пример CSV:

```csv
value_code;name;parent_code
BRICK;Кирпич;
AERATED;Газобетон;BRICK
```

Пример JSON:

```json
{
  "rows": [
    { "value_code": "BRICK", "name": "Кирпич", "parent_code": null },
    { "value_code": "AERATED", "name": "Газобетон", "parent_code": "BRICK" }
  ]
}
```

Обработка выполняется в одной транзакции:

1. Проверяется паспорт и дата.
2. Создаётся черновик версии с номером `max(version_id) + 1`.
3. Файл преобразуется в JSON.
4. Строки проверяются по `fields`.
5. Пишется SQL-файл данных.
6. Создаётся секция `table_name_version_id`.
7. Строки вставляются пачками до 1000.
8. Предыдущая действующая версия получает `closed` и `valid_to = valid_from - 1 день`.
9. Новая версия получает `active` и `valid_from`.
10. Транзакция фиксируется.

Если любой шаг не выполнен, транзакция откатывается: версия, секция и строки не сохраняются. SQL-файл, уже записанный на диск, остаётся для диагностики.

Ответ `201`:

```json
{
  "dictionary_version_id": "f3a8c1d2-6b44-4e90-8a17-2c5d9e0b7f31",
  "version_id": 4,
  "status": "active",
  "valid_from": "2026-10-23",
  "valid_to": null,
  "row_count": 2,
  "closed_version_id": 3,
  "closed_valid_to": "2026-10-22",
  "data_sql_path": "db/sql-data/wall_material/2026.10.23 16.10.00 - wall_material.sql"
}
```

Правила даты:

- `valid_from` не может быть раньше или равен `valid_from` действующей версии.
- Если действующей версии нет, ограничение только на корректность даты.
- Для первой версии `closed_version_id` и `closed_valid_to` равны `null`.

Ошибки:

- `dictionary_not_found` — нет справочника.
- `dictionary_inactive` — паспорт не принимает новые версии.
- `invalid_valid_from` — дата не проходит проверку.
- `unsupported_media_type` — не CSV и не JSON.
- `file_too_large` — файл больше 100 МБ.
- `empty_file` — файл пуст.
- `invalid_file` — файл не разобран.
- `unknown_field` — колонка, которой нет в `fields`.
- `missing_field` — нет обязательной колонки.
- `duplicate_value_code` — повтор `value_code` внутри версии.
- `invalid_value` — значение не соответствует типу или nullable.
- `script_failed` — SQL не выполнен.

### 2.5. Скачивание версии

`GET /admin/dictionaries/{dictionary_code}/versions/{version_id}/download`

Ответ `200`:

- `Content-Type: application/json; charset=utf-8`
- `Content-Disposition: attachment; filename="WallMaterial_v4.json"`

```json
{
  "dictionary_code": "WallMaterial",
  "version_id": 4,
  "version_status": "active",
  "valid_from": "2026-10-23",
  "valid_to": null,
  "archived": false,
  "fields": [
    {
      "code": "parent_code",
      "name": "Родительский код",
      "type": "string",
      "length": 500,
      "nullable": true
    }
  ],
  "rows": [
    {
      "value_code": "BRICK",
      "name": "Кирпич",
      "parent_code": null
    }
  ]
}
```

Правила:

- Скачивать можно действующую и закрытую версию.
- Черновик не скачивается: загрузка выполняется синхронно, отдельного черновика для скачивания нет.
- Архивированная версия возвращает `410 version_archived`.
- `rows` отдаются в порядке `value_code`.

Ошибки:

- `dictionary_not_found`
- `version_not_found`
- `version_not_ready` — версия ещё не действующая и не закрытая.
- `version_archived` — данные отсоединены.

### 2.6. Архивация версии

`POST /admin/dictionaries/{dictionary_code}/versions/{version_id}/archive`

Архивировать можно только закрытую версию. Секция версии отсоединяется от родительской таблицы, строка каталога сохраняется.

Ответ `204` без тела.

Правила:

- Активная и черновая версия не архивируются: `409 version_not_closed`.
- Повторная архивация уже архивированной версии возвращает `204`.
- После архивации чтение этой версии через сервисный API возвращает `archived: true` и не отдаёт строки.
- Скачивание архивированной версии недоступно: `410 version_archived`.

Ошибки:

- `dictionary_not_found`
- `version_not_found`
- `version_not_closed`
- `archive_failed`

## 3. Сервисный API чтения

Сервисный контур читает только простые списки: `value_code` и `name`. Дополнительные поля в ответ не входят.

### 3.1. Выбор редакции

Одновременно можно передать только один признак:

| Что передано | Какая версия |
|---|---|
| ничего | Действующая версия |
| `on_date` | Версия, в период которой попадает дата включительно |
| `version_id` | Указанная действующая или закрытая версия |

Правила:

- `on_date` и `version_id` вместе — `400 version_selector_conflict`.
- День вне всех периодов не переносится на соседнюю версию: `404 date_out_of_range`.
- Черновик не читается: `409 version_not_published`.
- Неактивный справочник читается: уже выпущенные версии остаются доступными.
- `archived: true` означает, что секция отсоединена. Строк нет, но факт существования версии сохраняется.

### 3.2. Одно значение

`GET /dictionaries/{dictionary_code}/values/{value_code}`

Параметры:

| Параметр | Тип | Обязателен | Описание |
|---|---|---|---|
| `on_date` | string | нет | Дата `YYYY-MM-DD` |
| `version_id` | integer | нет | Номер версии |

Ответ `200`:

```json
{
  "dictionary_code": "WallMaterial",
  "version_id": 4,
  "version_status": "active",
  "valid_from": "2026-10-23",
  "valid_to": null,
  "archived": false,
  "result": "present",
  "value_code": "BRICK",
  "name": "Кирпич"
}
```

`result`:

| Значение | Что означает |
|---|---|
| `present` | Код есть в этой версии |
| `absent` | Версия есть, кода в ней нет |
| `archived` | Секция версии отсоединена, подтвердить код нельзя |

При `result = absent` или `archived` поле `name` равно `null`.

Ошибки:

- `dictionary_not_found`
- `version_not_found`
- `version_not_published`
- `no_active_version`
- `date_out_of_range`
- `version_selector_conflict`
- `invalid_request`

### 3.3. Страница версии

`GET /dictionaries/{dictionary_code}/values`

Параметры:

| Параметр | Тип | Обязателен | Описание |
|---|---|---|---|
| `on_date` | string | нет | Дата `YYYY-MM-DD` |
| `version_id` | integer | нет | Номер версии |
| `limit` | integer | нет | 1…1000, по умолчанию 100 |
| `cursor` | string | нет | Продолжение страницы |

Ответ `200`:

```json
{
  "dictionary_code": "WallMaterial",
  "version_id": 4,
  "version_status": "active",
  "valid_from": "2026-10-23",
  "valid_to": null,
  "archived": false,
  "items": [
    {
      "value_code": "BRICK",
      "name": "Кирпич"
    }
  ],
  "next_cursor": null
}
```

Правила:

- Страница упорядочена по `value_code`.
- `cursor` относится к той же версии; при продолжении передаётся тот же выбор редакции.
- Пустая версия возвращает `items: []`, а не ошибку.
- Архивированная версия возвращает `archived: true` и `items: []`.
- `limit` вне диапазона или чужой `cursor` — `400 invalid_request`.

Ошибки те же, что у чтения одного значения.

### 3.4. Проверка ссылок

`POST /dictionaries/{dictionary_code}/values/check`

Тело:

```json
{
  "version_id": 4,
  "value_codes": ["BRICK", "PAPER"]
}
```

Правила:

- `version_id` обязателен.
- `value_codes` — от 1 до 1000 уникальных кодов.
- Повтор кода в запросе возвращается один раз.
- Проверка не пишет данные.
- Проверяется секция указанной версии, без выбора по дате.
- Если версия архивирована, у всех кодов `result = archived`.

Ответ `200`:

```json
{
  "dictionary_code": "WallMaterial",
  "version_id": 4,
  "version_status": "active",
  "valid_from": "2026-10-23",
  "valid_to": null,
  "archived": false,
  "items": [
    {
      "value_code": "BRICK",
      "result": "present",
      "name": "Кирпич"
    },
    {
      "value_code": "PAPER",
      "result": "absent",
      "name": null
    }
  ]
}
```

Ошибки:

- `dictionary_not_found`
- `version_not_found`
- `version_not_published`
- `invalid_request`

## 4. Сводная таблица ошибок

| Код | HTTP | Где |
|---|---|---|
| `invalid_request` | 400 | Все контракты |
| `version_selector_conflict` | 400 | Сервисный API |
| `dictionary_not_found` | 404 | Все контракты |
| `version_not_found` | 404 | Все контракты |
| `no_active_version` | 404 | Сервисный API |
| `date_out_of_range` | 404 | Сервисный API |
| `dictionary_already_exists` | 409 | Создание справочника |
