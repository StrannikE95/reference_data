## Модуль справочников: создание и загрузка

Экраны, которыми смотрят каталог, заводят справочник, заливают черновик и публикуют версию. 

Это части одного модуля и одной базы. Публикация версии — одна транзакция каталога и события. Кэша на этих экранах нет: его обновляет сервис чтения по событию публикации.

## Глоссарий

### Части

**Профиль** — сохранённый SQL создания таблиц в том виде, в котором справочник распространяется. Для материала стен это один `CREATE TABLE` с колонками `value_code` и `name`. Для набора это несколько таблиц, их ключи и связи. Модуль по этому SQL строит размещение и временные таблицы загрузки. В каталоге профиля нет: там только `table_name` или `schema_name`.

**Размещение** — действия с физическими таблицами PostgreSQL. Родительская таблица — секционированная таблица без своих строк, например `wall_material ... PARTITION BY LIST (version_id)`. Секция — `wall_material_12` на конкретный `version_id`. При создании справочника появляются только родительские таблицы. Секции появляются вместе с черновиком версии.

**Каталог** — таблицы `dictionary` и `dictionary_version`. Паспорт — строка `dictionary`: код, название, владелец, источник, статус. Строки значений в каталог не входят.

| Часть | Что делает |
|---|---|
| **Профиль** | Хранит SQL создания исходных таблиц. По нему строятся родительские таблицы и временные таблицы загрузки |
| **Каталог** | Хранит паспорт `dictionary` и строки `dictionary_version` |
| **Размещение** | Создаёт родительские таблицы `PARTITION BY LIST (version_id)`, пустые секции черновика и отсоединяет секцию закрытой версии |
| **Загрузка черновика** | Принимает SQL заполнения исходных таблиц, исполняет его во временных таблицах, копирует строки в секции черновика, проверяет их |
| **Публикация** | Переводит черновик в `active`, закрывает прежнюю действующую версию и пишет событие в той же транзакции |
| **Сервис чтения** | Выбирает редакцию и отдаёт строки. В нём же каталог в памяти, карты версий, прогрев и снятие карты |

## Функционал UI администратора

### 1. Просмотр каталога

Экран читает `dictionary` и `dictionary_version`. Строки значений, секции и кэш на нём не показываются.

### 2. Добавление профиля

Участвуют профиль, размещение и каталог. Справочник заводится один раз.

На входе:
- поля паспорта: `dictionary_code`, название, владелец, источник;
- SQL создания таблиц в исходном виде, без `version_id`.

Модуль сохраняет этот SQL как профиль. Из него он добавляет `version_id` в первичный ключ, уникальность и внешние ключи, создаёт родительские таблицы без секций и пишет паспорт в `dictionary` со статусом `active`. Одна таблица даёт `table_name`, несколько таблиц — `schema_name`. Имя дальше не меняется. Секционированный SQL оператор не приносит.

Исходные таблицы в рабочей схеме не остаются. Сохранённый SQL поднимает временные таблицы на загрузке версии.
SQL регистрации исполняется только как создание таблиц. Запрос на удаление, правку каталога или чужой схемы модуль не выполняет.
Строка версии на этом шаге не создаётся. Секций ещё нет. Кэш не меняется: читать пока нечего.

### 3. Добавление версии

Участвуют каталог, размещение и загрузка черновика. Публикация на этом экране не выполняется. Один и тот же порядок для простого списка и для набора. Число таблиц и имена колонок берутся из профиля.

Черновик создаётся всегда, когда его ещё нет: строка `dictionary_version` и пустые секции этого номера появляются одной операцией. `version_id` — на единицу больше максимального номера этого справочника. Отдельного признака «создать черновик» нет.

На входе:
- вид поставки;
- SQL заполнения таблиц в исходном виде.

**Полный дамп** — обычный путь. Секции черновика очищаются и заполняются заново. Повторная загрузка того же черновика делает то же самое.

**Инкремент** доступен, когда в профиле описано, как дельта ложится на действующую версию: новая строка, изменение, удаление. Модуль копирует строки действующей версии в черновик с новым `version_id` и применяет дельту. Пока такого описания нет, экран принимает только полный дамп.

SQL заполнения исполняется во временных таблицах, созданных из SQL профиля. Затем модуль копирует строки в секции черновика и проставляет `version_id`:

```sql
INSERT INTO wall_material (version_id, wall_material_id, value_code, name)
SELECT 12, gen_random_uuid(), value_code, name
FROM staging.wall_material;
```

Для набора такой оператор строится на каждую таблицу. Сначала копируется родитель, потом зависимая таблица. После копирования временные таблицы удаляются.
Загрузка проверяет строки: непустой простой список, уникальный `value_code`, внешние ключи внутри этого номера, секции во всех таблицах набора.
До публикации сервис чтения эти строки не отдаёт. Отмена черновика удаляет его секции и строку каталога, события нет.

### 4. Активация версии

Участвует публикация. Переходы `draft → active` и прежний `active → closed` выполняются одной командой. Двух независимых переключателей статуса нет.

На входе — `valid_from`. Модуль ставит предыдущей действующей версии `valid_to` на день раньше и в той же транзакции пишет событие: код справочника, новый `version_id`, `valid_from`, номер прежней действующей версии.

Публикация проходит, когда версия — черновик этого справочника, простой список не пуст, у набора секции этого номера есть во всех таблицах схемы, `valid_from` заполнен, не позже дня публикации и, если действующая версия есть, строго позже её `valid_from`.

Откат транзакции откатывает и событие. Черновик и его секции остаются. Закрыть действующую версию отдельной командой нельзя.

## Прочие учавствующие модули

### 7. Обновление кэша

Участвует только сервис чтения. Загрузка и публикация в память экземпляров не пишут.

1. Публикация оставляет событие.
2. Каждый экземпляр читает его своей группой потребителя.
3. Экземпляр заново читает каталог этого справочника и, если строк не больше порога, собирает карту новой действующей версии.
4. Карта прежней версии остаётся, пока её секция присоединена.

Архив идёт тем же путём: событие отсоединения помечает секцию отсоединённой и удаляет карту этой версии. Пропущенное событие подбирает периодическое перечитывание каталога.
