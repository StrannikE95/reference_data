# Секционирование таблиц справочника

Как строки версии физически лежат в PostgreSQL. 

Секционируются и таблица простого списка, и каждая таблица набора. Способ один.

## 1. Что такое секция

Секционирование делит одну логическую таблицу на несколько физических. Строки родительской таблицы не хранятся: каждая строка попадает ровно в одну секцию по значению ключа.

Ключ — `version_id`, способ деления — `PARTITION BY LIST`. Новая версия добавляет секцию. Имя таблицы простого списка и имя схемы набора при этом не меняются.

Запрос с условием `version_id = 12` планировщик сужает до секции этой версии. Вставка с `version_id = 13` пишется в секцию 13. Секцию можно отсоединить и унести в архив, не трогая остальные версии.

`version_id` в этих таблицах — обычное число, не внешний ключ на каталог. Иначе каждая таблица каждого справочника была бы связана с одной `dictionary_version`, и удаление или смена ключа версии проверяли бы их все.

## 2. Простой список

```sql
CREATE TABLE wall_material (
    version_id                   integer NOT NULL,
    wall_material_id             uuid    NOT NULL,
    value_code                   varchar NOT NULL,
    name                         varchar NOT NULL,
    PRIMARY KEY (version_id, wall_material_id),
    UNIQUE (version_id, value_code)
) PARTITION BY LIST (version_id);

CREATE TABLE wall_material_12
    PARTITION OF wall_material FOR VALUES IN (12);

INSERT INTO wall_material (version_id, wall_material_id, value_code, name)
VALUES (12, '...', 'BRICK', 'Кирпич');
```

Архивация: `ALTER TABLE wall_material DETACH PARTITION wall_material_12`.

## 3. Набор из двух таблиц

Адресный объект и дом. Ключ связи включает `version_id`, поэтому дом из версии 13 ссылается только на объект той же версии. Загрузка версии создаёт секцию в каждой таблице набора.

```sql
CREATE TABLE addr_object (
    version_id        integer NOT NULL,
    addr_object_id    uuid    NOT NULL,
    name              varchar NOT NULL,
    PRIMARY KEY (version_id, addr_object_id)
) PARTITION BY LIST (version_id);

CREATE TABLE addr_house (
    version_id        integer NOT NULL,
    addr_house_id     uuid    NOT NULL,
    addr_object_id    uuid    NOT NULL,
    house_number      varchar NOT NULL,
    PRIMARY KEY (version_id, addr_house_id),
    FOREIGN KEY (version_id, addr_object_id)
        REFERENCES addr_object (version_id, addr_object_id)
) PARTITION BY LIST (version_id);

CREATE TABLE addr_object_12
    PARTITION OF addr_object FOR VALUES IN (12);

CREATE TABLE addr_house_12
    PARTITION OF addr_house FOR VALUES IN (12);
```

Версия 13 — секции `addr_object_13` и `addr_house_13`. Старые строки не копируются и не меняются.

## 4. Ограничения

- Первичный и уникальный ключ обязаны включать `version_id`. Один и тот же идентификатор объекта может повториться в другой версии и не может повториться дважды внутри одной.
- Внешний ключ на секционированную таблицу тоже включает `version_id`. Строка версии 13 не связывается со строкой версии 12.
- Запрос без `version_id` обходит все секции. Индекс по идентификатору объекта у каждой секции свой, общего индекса на все версии нет.
- Смена `version_id` у уже записанной строки — это перенос в другую секцию, а не правка поля на месте.
- Много секций замедляет планирование запроса. Десятки версий на таблицу нормальны, тысячи секций на одну таблицу — нет.

## 5. Загрузка обновления набора

В официальной поставке ФИАС поля `version_id` нет. Готовый загрузчик, который пишет в таблицы исходного вида, в секционированные таблицы сам не попадает: у них другой первичный ключ.

Инструмент модуля не разбирает формат поставки заново. Файлы загружаются как есть во временные таблицы исходного вида. Затем строки копируются в секцию с постоянным номером версии:

```sql
INSERT INTO addr_object (version_id, addr_object_id, name)
SELECT 12, addr_object_id, name
FROM staging.addr_object;
```

Разбор формата остаётся у средства, которое уже умеет читать поставку. Часть модуля — создать секции этой версии и проставить в них `version_id`.
