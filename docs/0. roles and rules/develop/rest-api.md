# ИИ-агент: модуль справочников (service_app) — чтение

## Правила разработки REST API для справочников

### 1. Архитектура слоёв

- Вызов идёт строго: Controller → Service → DB
- Service собирает ответ контракта по одному справочнику
- DB отдаёт паспорт, версии из каталога и строки одной секции

### 2. HTTP-маршруты

| Операция | Маршрут | Метод |
|---|---|---|
| Одно значение | `/dictionaries/{dictionary_code}/values/{value_code}` | GET |
| Страница | `/dictionaries/{dictionary_code}/values` | GET |
| Проверка ссылок | `/dictionaries/{dictionary_code}/values/check` | POST |

### 3. Валидация запроса в Controller

- Два признака редакции сразу (`on_date` + `version_id`) → `version_selector_conflict` (400)
- Пустая проверка ссылок → `invalid_request` (400)
- Больше 1000 кодов в проверке → `invalid_request` (400)
- `limit` вне 1…1000 → `invalid_request` (400)
- Неразборчивый курсор → `invalid_request` (400)

### 4. HTTP-коды ответов

| Ошибки | Код |
|---|---|
| `version_selector_conflict`, `invalid_request` | 400 |
| `dictionary_not_found`, `version_not_found`, `version_not_published`, `no_active_version`, `date_out_of_range` | 404 |
| `present`, `absent`, `archived` (результаты запроса) | 200 |

### 5. Выбор редакции в Service

- `on_date` — версия, в чей период день попадает включительно. Пустой `valid_to` — открытый конец. Нет периода → `date_out_of_range`
- `version_id` — строка каталога. Нет строки → `version_not_found`. Статус `draft` → `version_not_published`
- Без параметров — версия со статусом `active`. Нет → `no_active_version`
- Периоды опубликованных версий не пересекаются. Если день попал в два периода → ошибка чтения каталога
- Если переданный признак редакции разрешается в другой `version_id`, чем у курсора → `invalid_request`

### 6. Обработка секции в Service

- Секция отсоединена: `result = archived`, пустая подпись
- Секция на месте и карта в памяти: поиск по карте `value_code → name`
- Секция на месте, карты нет: вызов DB по `version_id` и кодам
- Найденный код: `result = present`, подпись
- Не найденный код: `result = absent`, пустая подпись
- Повтор кода в проверке → одна строка ответа до чтения секции

### 7. DB: каталог

Отдаёт по `dictionary_code`: статус паспорта, опубликованные версии (`active` и `closed`), для каждой — `version_id`, статус, `valid_from`, `valid_to`, `table_name`, признак присоединения секции.

### 8. DB: секция

Таблица из `table_name`, всегда с условием `version_id`:
- Строка по `version_id` и `value_code`
- Строки по `version_id` и списку кодов
- Страница: `value_code` больше границы курсора, порядок по `value_code`, не больше `limit`
- Число строк секции — для решения Service,是否需要 собрать карту версии

### 9. Курсор пагинации

- Несёт `version_id` выбранной редакции и последний `value_code` страницы
- Следующий запрос передаёт тот же признак редакции

### 10. Кэш в памяти

- Ключ каталога — один на процесс
- Ключ версии: `dictionary_code` + `version_id`
- Кэш держит статус паспорта и опубликованные версии с периодами, карту `value_code → name`
- Карта версии собирается при прогреве или при первом чтении
- Карта версии хранится, пока секция присоединена
- Порог тяжести версии: 10 000 строк (настройка). Тяжелее → всегда читается из DB
- Параллельные чтения одной версии в одном процессе ждут одну загрузку

### 11. Инвалидация кэша по событиям

| Событие | Приходит | Действие |
|---|---|---|
| Публикация | Код справочника, новый `version_id`, `valid_from`, номер прежней действующей версии | Заново читает каталог, прогревает новую active версию. Прежняя остаётся |
| Архив | Код справочника и `version_id` | Помечает секцию отсоединённой, удаляет карту версии |

- Каждый экземпляр — своя группа потребителя, все получают публикации и архивы
- Periodически экземпляр перечитывает каталог из базы
- Пока секция присоединена, карта версии при перечитывании остаётся
- Отсоединённая секция удаляет свою карту

### 12. Прогрев при старте

- Прочитать паспорта и опубликованные версии всех справочников
- Для каждой `active` версии узнать число строк секции
- Если строк ≤ порога (10 000) — прочитать секцию и собрать карту `value_code → name`
- Экземпляр принимает запросы, когда каталог загружен
- До сборки карты версии читаются из секции
- Сбой одного списка оставляет его на чтении из секции, остальные прогреваются
- Закрытая версия попадает в карту при первом чтении тем же порогом
- После публикации новый `version_id` прогревается по тому же правилу, без перезапуска
